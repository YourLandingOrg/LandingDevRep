## Dónde escribir qué

- **Una tarea, error o cambio concreto** → abre un **Issue**.  
- **Retroalimentación sobre la página** (Customer Success) → Issue con la etiqueta `feedback`.
- **Comunicados, avisos y dudas generales** → pestaña **Discussions**.
- **Ver el avance y quién hace qué** → el **Project** de la organización.

## Cómo trabajamos (programadores)

1. Toma un issue asignado a ti y muévelo a "En progreso" en el Project.
2. Crea una rama desde `main` con este formato: `tipo/descripcion-corta`
   (ejemplos: `feature/seccion-contacto`, `fix/menu-movil`).
3. Haz commits pequeños y con mensajes claros, en español, que expliquen qué cambió.
4. Abre un **Pull Request** hacia `main` y enlaza el issue (por ejemplo, escribiendo `Closes #12`).
5. El lead coder revisa. No se aprueba el PR propio.
6. Customer Success revisa la vista previa y comenta en el PR si algo no coincide con lo prometido.
7. Cuando hay aprobación, se hace merge y se mueve el issue a "Hecho".

## Reglas del equipo

- Nadie sube cambios directamente a `main`; todo pasa por Pull Request.
- Una rama por tarea, y se borra al hacer merge.
- Los comentarios de retroalimentación deben decir qué se esperaba, qué se ve y, si es posible, una captura.
- Los issues se responden en un máximo de 9 días hábiles.
- No se suben contraseñas, claves ni datos personales.
